# Упражнения по языку C

26 самостоятельных программ: 20 решений по 28 фотографиям презентации,
5 новых номерных заданий по трём видео главы 5 и один пример трассировки
указателей из первой лекции. Каждый файл
`exercise_глава_номер.c` содержит свою функцию `main` и запускается отдельно.
Код оформлен в едином учебном стиле: стандартные библиотеки C, отступы
в четыре пробела, короткие комментарии и простые функции.

## Запуск в Visual Studio

1. Откройте **Exercises.slnx** из этой папки в установленной Visual Studio 2026.
2. В обозревателе решений нажмите правой кнопкой на нужное упражнение
   и выберите **Set as Startup Project / Назначить запускаемым проектом**.
3. Нажмите **Ctrl+F5** для сборки и запуска.

Для каждого упражнения уже создан отдельный проект в `projects`.
У всех проектов выбран язык C17 и платформа x64. Не нужно добавлять все
`.c` в один исполняемый проект: у каждого своя точка входа `main`.
Исходный проект `C_Methods` оставлен без изменений.

В установленной среде создание отладочного PDB при линковке вызвало
`LNK1101: incorrect MSPDB140.DLL version`. Поэтому в этих проектах отключена
генерация PDB линковщиком: обычная сборка и запуск через Ctrl+F5 работают,
но пошаговая отладка по исходному коду потребует исправления компонента
Visual Studio и включения **Linker → Debugging → Generate Debug Info**.

## Сборка из PowerShell

Откройте терминал в этой папке. Скрипт сам находит компилятор Visual Studio
с установленным компонентом **Desktop development with C++**:

```powershell
.\build.ps1
.\bin\exercise_2_03.exe
```

Собрать только одно задание:

```powershell
.\build.ps1 exercise_1_19
.\bin\exercise_1_19.exe
```

Программы обработки текста читают стандартный ввод до EOF. В Windows
после ввода строк нажмите **Ctrl+Z**, затем **Enter** на новой строке.
Отсутствие результата до завершения ввода нормально для счётчиков.
Для точной работы с файлами используйте перенаправление в `cmd`:

```bat
bin\exercise_1_19.exe < input.txt > output.txt
bin\exercise_1_23.exe < chapter_1\exercise_1_03.c > without_comments.c
```

Пример для PowerShell:

```powershell
"hello" | .\bin\exercise_1_19.exe
# olleh
```

PowerShell при такой передаче добавляет перевод строки. Для проверки
ввода без завершающего перевода строки предусмотрен `test.ps1`.

Для другого компилятора можно собрать любой файл отдельно:

```sh
gcc -std=c17 -Wall -Wextra -Wpedantic chapter_1/exercise_1_19.c -o exercise_1_19
```

Либо использовать CMake:

```sh
cmake -S . -B build
cmake --build build --config Debug
```

## Примечания к решениям

- **1-1:** в комментарии перечислены эксперименты с пропущенной точкой
  с запятой, кавычкой и закрывающей скобкой. Рабочая версия компилируется;
  для эксперимента изменяйте копию файла. Текст диагностики зависит от компилятора.
- **1-2:** обычная сборка показывает допустимые escape-последовательности.
  Для опыта с недопустимой `\q` откройте Developer Command Prompt в этой
  папке и выполните команду ниже. Ожидается диагностика компилятора;
  результат запуска после неё не переносим между компиляторами.
- **1-11:** слово — последовательность символов между пробелами,
  табуляциями и переводами строки, как в примере преподавателя.
  Количество строк — количество `\n`; последняя строка без `\n` увеличивает
  число слов и символов, но не счётчик переводов строк.
- **1-17:** порог — строго больше 80 символов, без учёта `\n`.
- **1-18 и 1-19:** буфер увеличивается по мере необходимости; длинные
  строки не обрезаются. В 1-19 используется обычная строка C без встроенных
  нулевых байтов; разворот побайтовый, для учебного ASCII-текста.
- **1-20 и 1-21:** табуляция выравнивает на позиции через каждые 8 колонок.
  Шаг задан константой `TAB_WIDTH`, поскольку по условию он фиксирован.
  Если достаточно одного пробела, 1-21 предпочитает пробел табуляции.
  Обычный символ занимает одну колонку; обработка экранных эффектов backspace
  и управляющих последовательностей терминала не входит в эти упражнения.
- **1-22:** ширина — 80 колонок. Табуляции раскрываются; перенос делается
  по последнему доступному пробелу, а разделительные пробелы у места переноса
  удаляются. Слово длиннее 80 символов разбивается на части.
- **1-23:** обрабатываются `/* ... */`, `// ...`, строки и символьные
  литералы с экранированием. Комментарий заменяется пробелом, чтобы
  `int/**/x` не превратилось в `intx`. Переводы строк внутри комментариев
  сохраняются. Склейка `\` + перевод строки выполняется перед разбором.
- **1-24:** проверяются вложенность `()`, `[]`, `{}`, незакрытые кавычки
  и комментарии. Лимит вложенности — 1000, превышение сообщается как ошибка.
  Это не полный компилятор: директивы условной компиляции, макросы, диграфы
  и триграфы не интерпретируются. Ограничение на препроцессор относится
  также к 1-23.
- **2-1:** целочисленные диапазоны печатаются из `limits.h` и независимо
  вычисляются безопасной беззнаковой арифметикой. Для вычисления отрицательных
  границ принято представление two's complement, используемое на этом ПК.
  Диапазоны вещественных типов приведены из `float.h`; дополнительная
  усложнённая часть с их самостоятельным вычислением не реализована.
  `FLT_MIN` и аналоги — минимальные положительные нормализованные значения,
  а не отрицательные границы. Размеры получаются через `sizeof`.
- **2-3:** поддерживаются `0x`, `0X`, оба регистра букв. Неверная строка,
  отсутствие цифр или переполнение `int` дают `-1`.

Эксперимент 1-2 (Developer Command Prompt; папки `bin` и `obj` создаются
обычным запуском `build.ps1`):

```bat
cl /nologo /TC /std:c17 /W4 /DTEST_UNKNOWN_ESCAPE chapter_1\exercise_1_02.c /Foobj\unknown_escape.obj /Febin\unknown_escape.exe
```

Фактические результаты экспериментов на установленном MSVC:

| Изменение | Диагностика |
| --- | --- |
| 1-1: убрать `;` после `printf` | C2143: missing `;` before `return` |
| 1-1: убрать закрывающую кавычку | C2001: newline in string literal; затем C2143 |
| 1-1: убрать закрывающую `}` | C1075: no matching token found |
| 1-2: включить `\q` | C4129: unrecognized character escape sequence |

При продолжении компиляции 1-2 MSVC напечатал `Unknown escape: q`.
Это наблюдение для данного компилятора, а не правило языка C.

10 000 символов, отсутствие последнего `\n`, соответствие `entab`/`detab`,
перенос строк, комментарии внутри кавычек, экранирование, ошибки вложенности
и соответствие вычисленных границ стандартным заголовкам. Отдельный
тест `tests/test_htoi.c` проверяет 18 вариантов, включая `INT_MAX`,
переполнение, пустую строку и неверные цифры.
