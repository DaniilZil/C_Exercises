## Как запустить

Каждый `.c` — отдельная программа с собственной `main`. Откройте
`Exercises.slnx` в родительской папке и назначьте нужное упражнение
запускаемым проектом. Либо откройте PowerShell в папке `Exercises`:

```powershell
.\build.ps1
# Можно собрать только одно:
.\build.ps1 exercise_5_03
```

**5-3:** введите две строки. Вывод — первая строка с добавленной второй.
Переводы строк между ними в результат не включаются:

```powershell
"hello `nworld" | .\bin\exercise_5_03.exe
# hello world
```

Функция `mystrcat` использует только указатели. Префикс `my` отличает
учебную реализацию от стандартной функции. Массив назначения в `main`
вмещает обе строки. Каждая входная строка ограничена 999 байтами;
переполнение и отсутствие второй строки сообщаются как ошибка.

**5-4:** также введите две строки; вывод `1` означает совпадение суффикса,
`0` — отсутствие совпадения. Регистр учитывается; пустой суффикс подходит
к любой строке. Ввод ограничен 999 байтами на строку.

```powershell
"hello world`nworld" | .\bin\exercise_5_04.exe
# 1
"hello world`nhello" | .\bin\exercise_5_04.exe
# 0
```

**5-7:** вводите строки до EOF (в Windows: Ctrl+Z и Enter на новой строке).
Вывод — строки в порядке `strcmp`, с сохранением повторов и пустых строк.
Последняя строка без завершающего Enter также учитывается.

```powershell
"zebra`napple`nbanana" | .\bin\exercise_5_07.exe
# apple
# banana
# zebra
```

`main` владеет массивом `linestor` на 10 000 байт и передаёт его в
`readlines`. Позиция хранится в переменной `used` типа `size_t`;
`lineptr` получает адреса начала строк в этом массиве. Функция не вызывает
`alloc` или `malloc`. Ограничения: 5000 строк, 999 байт в одной строке,
10 000 байт суммарно с учётом завершающих `\0`. При превышении программа
выдаёт ошибку, а не обрезает текст. Сортируется массив указателей
стандартной `qsort`; сами строки остаются на месте.

**5-8:** запустите программу без ввода. Она показывает четыре случая
со слайда, включая две ошибочные даты:

```text
day_of_year(1988, 2, 29) = 60
day_of_year(2020, 2, 31) = -3 (invalid day)
month_day(1988, 60): status=0, month=2, day=29
month_day(1999, 366): status=-4, month=0, day=0
```

`day_of_year` возвращает порядковый номер дня либо отрицательный код.
`month_day` возвращает `0` при успехе, передаёт месяц и день через указатели
и возвращает отрицательный код при ошибке. В отличие от исходного `void`
на слайде, возвращаемый тип `int` позволяет проверить статус. При ошибке
доступные выходные переменные обнуляются.

| Код | Значение |
| --- | --- |
| -1 | Год меньше 1 |
| -2 | Месяц вне диапазона 1–12 |
| -3 | Недопустимый день месяца |
| -4 | Порядковый номер дня вне диапазона 1–365/366 |
| -5 | Нулевой выходной указатель или один адрес для двух результатов |

**5-10:** передавайте каждый операнд и оператор отдельным аргументом.
Поддерживаются `+`, `-`, `*`, `/`, `%`, отрицательные и дробные числа:

```powershell
.\bin\exercise_5_10.exe 2 3 4 + '*'
# 14
.\bin\exercise_5_10.exe 10 3 -
# 7
.\bin\exercise_5_10.exe -3 2.5 '*'
# -7.5
```

Для Visual Studio в новом проекте `exercise_5_10` уже заданы аргументы
`2 3 4 + *`. Их можно изменить в **Project Properties → Configuration
Properties → Debugging → Command Arguments**. Программа проверяет
числа, количество операндов, деление на ноль, переполнение вычисления
и лишние значения в стеке. `%` вычисляет вещественный остаток через `fmod`.

**Пример трассировки:** `exercise_5_trace.exe` выводит:

```text
15 15
10 10
```

После `*mp = *mp + *np` переменная `m` равна 15, а после
`*np = *mp - *np` переменная `n` равна 10. Исправлена опечатка слайда:
там написано `np = &np`, а по смыслу и пояснению преподавателя нужно
`np = &n`. Это отдельный ненумерованный пример, а не выдуманное задание 5-0.

## Замер скорости для 5-7

Замер выполнен 5 ноября 2026 года на этом компьютере, MSVC x64, C17, `/O2`.
Тест [benchmark_5_07.c](../tests/benchmark_5_07.c) сравнивает `readlines`
с вариантом на основе **статического `alloc` из лекции**, а не с `malloc`.
Используются одинаковые входные данные, функция чтения и копирование.
Совпадение всех полученных строк проверяется перед измерением.

В каждом из 5 раундов — 2000 чтений файла по 400 строк; порядок запуска
вариантов чередуется. Создание файла, сортировка и печать не измеряются.
Приведена медиана времени раунда:

| Вариант | Время |
| --- | --- |
| Исходный со статическим `alloc` | 0,230 с |
| Хранилище, переданное из `main` | 0,227 с |

В этом запуске отношение времени составило **1,013**, то есть новый вариант
занял примерно на **1,3% меньше времени**. Разница небольшая и может
находиться в пределах колебаний замера: гарантировать такое ускорение
нельзя. Статический `alloc` сам по себе очень прост, компилятор может его
встроить, а чтение символов занимает основную часть времени.

Повторить сборку тестов и замер из папки `Exercises`:

```powershell
.\test_chapter_5.ps1
.\bin\benchmark_5_07.exe
```

## Что проверено

Все 26 программ в общей папке компилируются с `/std:c17 /W4 /WX` и через
решение Visual Studio. Предыдущие 246 проверок и 18 случаев `htoi` прошли
повторно. Для новых программ пройдены 84 проверки запуска и вывода,
проверки указательных функций, точного заполнения хранилища, ошибок
ввода и калькулятора. Календарные функции проверены на всех **146 097 датах
полного 400-летнего цикла** и на недопустимых аргументах.

Настройка PDB в существующих проектах сохранена; ограничение пошаговой
отладки из-за ошибки компонента Visual Studio описано в общем README.
